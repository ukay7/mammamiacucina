# Manual production release — 30 September 2026

Update: production is moving to MySQL. Follow MYSQL-MIGRATION.md for the one-time cutover. The updated deploy-update.sh backs up either SQLite or MySQL; the original release notes below describe the pre-cutover installation.

Run the following as root on the existing production server. It assumes the established installation at `/var/www/mammamiacucina-app`, PHP 8.4, the `mmcdeploy` account, and SQLite. The updater stops if the database is not SQLite; arrange the correct database backup before proceeding in that case.

```bash
set -euo pipefail
cd /var/www/mammamiacucina-app
# Stop if the live checkout contains local code edits. Do not reset them.
test -z "$(sudo -H -u mmcdeploy git status --porcelain)" || { echo 'Live checkout has local changes; stop and review them.'; exit 1; }
previous=$(sudo -H -u mmcdeploy git rev-parse HEAD)
echo "Previous release: $previous"
sudo -H -u mmcdeploy git fetch origin
sudo -H -u mmcdeploy php8.4 website/artisan down --retry=60
sudo -H -u mmcdeploy git merge --ff-only origin/main
bash website/deploy-update.sh
```

The updater makes a private backup of the SQLite database, storage/uploads, environment and Nginx configuration; installs production Composer dependencies; applies pending migrations; seeds all delivery zones, services and 4,500 matrix cells while preserving admin-edited rates; rebuilds caches; reloads PHP; brings the site online; and checks the storefront and login URLs. It leaves the site in maintenance mode if a deployment step fails. Preserve the printed previous commit and backup path. Do not run `migrate:fresh`, replace the production database with the local database, or regenerate APP_KEY.

Ensure the scheduler is installed once (preserves other mmcdeploy cron entries):

```bash
cron_file=$(mktemp)
crontab -u mmcdeploy -l > "$cron_file" 2>/dev/null || true
if ! grep -Fq '/var/www/mammamiacucina-app/website && /usr/bin/php8.4 artisan schedule:run' "$cron_file"; then
  echo '* * * * * cd /var/www/mammamiacucina-app/website && /usr/bin/php8.4 artisan schedule:run >> /var/www/mammamiacucina-app/website/storage/logs/scheduler.log 2>&1' >> "$cron_file"
  crontab -u mmcdeploy "$cron_file"
fi
rm "$cron_file"
cd /var/www/mammamiacucina-app/website
sudo -H -u mmcdeploy php8.4 artisan migrate:status
sudo -H -u mmcdeploy php8.4 artisan schedule:list
```

After deployment:

- General Settings: enter the real warehouse From postal code and enable matrix delivery. The seeder does not overwrite these settings. M2N was only the local placeholder.
- Delivery Rates: confirm the five services, zone mappings and prices. Website checkout and POS should update the total when destination/service changes.
- Configure working production email credentials before asking customers to verify/reset passwords. Local testing used `MAIL_MAILER=log`, which does not deliver mail. After editing production `.env`, run `sudo -H -u mmcdeploy php8.4 artisan config:cache` from the website directory.
- Preserve existing production gateway settings and credentials; check the intended live payment mode in Gateway Settings before accepting online payments.
- Verify customer login/profile, admin customer management, product Individual/Business pricing, checkout/POS, order details and receipt delivery fields. Check the application log if any request fails.

Code, migrations, bundled catalogue assets and delivery seed data are included. Existing production records remain in place. Local test customers/orders and local database-only CMS/pricing edits are not copied to production.
