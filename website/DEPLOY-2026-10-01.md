# Numbering and business-details release

Deploy the new code and run the existing `website/deploy-update.sh` updater. It backs up the configured database, applies the business-details migration, and runs `app:initialize-numbering` while the site is in maintenance mode.

The numbering command supports SQLite and MySQL/MariaDB. It raises the next order ID to at least 3000 (`mmc-3000`) and the next customer ID to at least 4000. Existing orders, customer IDs, and links are preserved. If a sequence is already higher, it stays higher. Repeating the command cannot lower it.

To rerun numbering on production after deploying this code (run from your root PuTTY session):

```bash
cd /var/www/mammamiacucina-app/website
sudo -H -u mmcdeploy php8.4 artisan down --retry=60 &&
sudo -H -u mmcdeploy php8.4 artisan app:initialize-numbering --orders=3000 --customers=4000 &&
sudo -H -u mmcdeploy php8.4 artisan up
```

Pause any app queue/import workers that create orders or customers during the sequence update. If the command fails, the chained commands leave the site in maintenance mode; resolve the reported error before running `artisan up`. There is no database reset, customer deletion, or reseeding in this command.

Business fields are stored in `customers.business_bin`, `business_name`, `business_phone`, and `business_email`. Existing business accounts keep their data and must fill in missing business details when their profile is next saved. Login email and account type remain immutable in the customer profile.

## Email History and verification resend cooldown

Deploy the new migration with `php8.4 artisan migrate --force` before serving the updated code, then refresh the compiled views (`php8.4 artisan view:cache`). The existing deployment updater already runs migrations.

General Settings → Email History shows recipient, email type, subject, attempt timestamp, sending result, sent timestamp and message ID. History starts at installation; historical sends cannot be reconstructed. Private verification/reset URLs, message bodies, SMTP exception text and passwords are not stored in this table. Accepted is transport acceptance, not proof of inbox delivery. Log/array transports are marked Logged only.

Registration, customer/admin verification resends and POS invitations share a database-backed 10-minute cooldown per user. Resend buttons show the remaining time. Failed sending attempts release the cooldown for retry. Existing password reset token expiry/throttling is unchanged.

## Business account approval

Run migrations before enabling the updated application. Business approval is separate from email verification and active/inactive status. All business accounts without `business_approved_at`, including existing accounts, require administrator approval under Customer Management. The approval records its timestamp and administrator ID. No accounts are automatically approved during deployment.

Pending business customers see individual prices and cannot submit website orders or open their customer dashboard. Approved customers must also be active and email-verified to receive business pricing and dashboard access. Individual customer behavior is unchanged.

## Installable app (PWA)

The app is named Mamma Mia Cucina. Open `/app` after deployment. On supported Chromium browsers use Install Mamma Mia Cucina or the browser install menu. On iPhone use Safari Share → Add to Home Screen → Open as Web App. Production requires HTTPS. No app-store submission is required.

The service worker caches only the generic offline page and app icons. Private pages, API responses and POST requests are never stored by it. Orders, camera lookup and packing changes require connectivity. Reconnect and verify order status before retrying a request that lost its connection. Existing sessions and role permissions apply. No push notifications or offline order synchronization are included.

After deployment check `/manifest.webmanifest`, `/sw.js`, `/pwa/offline.html` and `/app`. Keep these static paths publicly accessible over HTTPS. Browser offline/reconnect testing passed locally; actual installation/camera permissions should also be checked on the warehouse phones against the live HTTPS site.
