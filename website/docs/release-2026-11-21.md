# Notification attachments release — 21 November 2026

Adds up to five private attachments (10 MB combined) to notification drafts, test emails and queued bulk sends. Supported formats: PDF, JPG/JPEG, PNG, WebP, DOC/DOCX and XLS/XLSX. Review screens, reports and test history list files; duplicate retains them. File changes require a fresh test. Missing or changed files stop the send for review. Includes a notification settings singleton fix for MySQL. Leads were discussed only and are not part of this release.

Validation: desktop/mobile workflow checks, full SQLite suite (652 tests, 13,506 assertions, no failures, one MySQL-only skip), then focused verification after the settings fix (35 SQLite tests / 356 assertions and 36 MySQL tests / 359 assertions, including the skipped case). Final attachment permission adjustment is covered by the same focused suites. All email providers were mocked; no live emails were sent.

## Update live in PuTTY as root

```bash
(
  set -e
  cd /var/www/mammamiacucina-app/website
  php8.4 -r 'if (!extension_loaded("gd")) { fwrite(STDERR, "PHP GD is required. Install php8.4-gd first.\n"); exit(1); }'
  sudo -H -u mmcdeploy php8.4 artisan down --retry=60
  sudo -H -u mmcdeploy git pull --ff-only origin main
  sudo -H -u mmcdeploy composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
  sudo usermod -a -G www-data mmcdeploy
  sudo install -d -o mmcdeploy -g www-data -m 2770 storage/app/private storage/app/private/notification-attachments
  sudo -H -u mmcdeploy php8.4 artisan config:clear
  sudo -H -u mmcdeploy php8.4 artisan route:clear
  sudo -H -u mmcdeploy php8.4 artisan migrate --force
  sudo -H -u mmcdeploy php8.4 artisan config:cache
  sudo -H -u mmcdeploy php8.4 artisan view:cache
  sudo -H -u mmcdeploy php8.4 artisan queue:restart
  sudo systemctl reload php8.4-fpm
  sudo -H -u mmcdeploy php8.4 artisan up
  sudo -H -u mmcdeploy git log -1 --oneline
)
```

The additive migration is `2026_11_20_190000_add_notification_attachments.php`. The existing scheduler is reused; no cron addition, Node build or data reseed is needed. The shared directory/group setup allows the HTTP uploader and CLI sender to access the same private files. Existing 100 MB PHP upload settings are sufficient; this module intentionally limits email attachments to 10 MB combined.

The command block stops at the first error. If it stops after maintenance starts, resolve that error before bringing the site online. After deployment, open Manage Email → Notifications, upload a file, save and send a test to your own inbox. Confirm receipt of the attachment before queuing a campaign. Do not run the live outbox just to verify deployment, as that sends queued messages.
