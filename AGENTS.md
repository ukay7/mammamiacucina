# Customer document theme

User-approved rule: all customer-facing printable/PDF documents (order confirmations, invoices, payment receipts, quotations, and future statements) must use the shared A4 document theme in website/resources/views/documents. Use the logo and configured company contact details at left, document type/number/date at right, cream information panels, gold rules, clear item/totals tables, payment/delivery details and a thank-you footer. Per the user's 12 November 2026 update, display the configured GST/HST number at the bottom right in the shared document footer, never in the header, across all print/PDF templates. Preserve each document's meaning: an order confirmation is not proof of payment; receipts confirm actual receipts; invoices have their own unique number. Never invent registration details or copy example financial amounts. Preserve invoice snapshots and label current balances as current. If a future request conflicts with this theme, alert the user before changing it and follow their explicit decision. Reuse the shared theme instead of duplicating styling.

PDF rendering with PNG logos requires PHP GD. Verify GD is enabled on deployment before running the email outbox.

User-approved exception (12 November 2026): Delivery Print is a landscape #10 / COM10 envelope (9.5 x 4.125 inches), following the supplied envelope reference and using configured company details and the order's delivery destination. The separate Delivery Form uses the shared A4 theme, contains no financial fields, and provides Receiver name and Receiver signature lines.

User-approved Delivery Form update (14 November 2026): Keep the shared A4 branding and omit product prices/order totals. Show sequential serial number, smaller photo, item code, the product's Premium Marketing Name, net carton weight (kg), pack weight (kg), pieces per carton and quantity. Replace the old receiver-name/signature lines with the supplied fulfillment-specific handover table: 10 steps for delivery, 4 for pickup. The delivery handover includes blank handwritten payment fields (CAD$, Cash/Cheque) as shown in the user's reference; these never contain system financial amounts or confirm payment automatically.
